# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

uzume-plugin-tracker is the Randomizer Tracker plugin (`uzume.tracker`): a spoiler-free tracker for randomized Pokémon runs on Omega Ruby / Alpha Sapphire. It records only what the player has seen through `uzume-plugin-soullink-core` (wild species per area with types and caught state, trainers' species, notes, types overview) and stores it per run or per game in the plugin store.

## Relation to Uzume

- Plugin for [Uzume](https://github.com/phabioo/uzume) (self-hosted retro gaming platform). Interface: `docs/architecture/12-plugins.md` and `docs/guides/plugin-api.md` in the Uzume repository.
- Plugin API v1 ships with Uzume since 0.11 (`docs/guides/plugin-api.md` there); the store used here ships with Uzume 0.20. Open API items are marked open, never invented.
- Runtime: Lua 5.4 in the Uzume sandbox; UI only as declarative building blocks (no QML).

## Working rules

- Repository language is English: code, comments, UI strings, docs, commit messages and PRs.
- Opus only orchestrates and writes no product code; implementation is done by the Sonnet 5.5 agents in `.claude/agents/`, searching and log reading by the Haiku agent `scout` (alias `haiku`).
- Briefs follow the template in `docs/workflow.md` (which also holds the token-saving rules).
- Opus verifies via `git diff --stat`, a targeted diff and the test result; commit/PR by Opus. One work package per thread, one topic per PR.

## Hard rules

- No ROMs, BIOS, firmware, game files, extracted assets, sprites, maps, text dumps or RAM dumps of real games in the repository or in tests. Tests use only synthetic data generated by code from documented formats.
- Nintendo/Pokémon names may appear as text identifiers only.
- Never put secrets in files, profiles or logs.
- Never overwrite saves silently.

## Languages

- Target versions are the German/EU releases first. Adapters support all language versions of a game where feasible, at least German and English.
- Names of species, moves, items and locations are read from the game at runtime so they appear in the game's language; they are never shipped as tables. Our own data tables are keyed by internal IDs, not names.
- Plugin UI strings come from i18n files (`i18n/`): English is the source, German the first translation.

## Status and commands

- Status: v0.2.0 (export of the notes and seen data as text in a copyable textarea); v0.1.1 (API namespace `uz`, falls back to `fb` on older apps); v0.1.0. Layout and design: `docs/architecture.md`.
- Sources are modules in `src/`; the sandbox has no `require`, so `lua5.4 tools/bundle.lua` generates the committed single `plugin/main.lua` (list new modules in `src/modules.txt`; `--check` fails when stale). Tests: `lua5.4 tests/run.lua` (fake `uz` in `tests/support/uz_mock.lua`, fake `pokemon.core` in `tests/support/fake_core.lua`, helpers in `tests/support/harness.lua`). Package: `python3 -I tools/package.py [--out DIR] [--tag vX.Y.Z]` builds the unsigned `<id>-<version>.uzplugin` (`--verify FILE` validates). CI (`.github/workflows/ci.yml`) runs bundle check, tests, changelog tool tests and packaging; the manual `release.yml` (input `tag` = `vX.Y.Z`, must equal the manifest version) attaches the package to a GitHub release.
- The SessionStart hook `.claude/hooks/session-start.sh` only prepares cloud sessions (installs `lua5.4` via apt if missing).
